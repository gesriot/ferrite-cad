# §25D — шаг привязки координат Line-вершин

В canvas нового или сохранённого Line Sketch есть компактный выбор
`Snap: Off / 0.1 mm / 1 mm / 5 mm / 10 mm`. По умолчанию Off. Это настройка
текущего редактора, не данные модели: новый черновик всегда начинается с Off.
Произвольного ввода шага, preferences, persisted schema и конфигурационного
файла нет.

Шаг задан в координатах документа (mm от начала XY) и не зависит от Fit, Reset,
DPI или масштаба автоматически рисуемой сетки. Выбранный шаг виден в ряду Snap
и в подписи canvas рядом с сеткой. Рисование сетки по-прежнему ограничено
примерно пятьюдесятью линиями; шаг привязки сетку не подменяет.

## Добавление и drag

- При включённом Snap свободный click, добавляющий вершину нового незамкнутого
  контура, округляет X и Y до ближайшего кратного шага. Половина шага округляется
  от нуля; отрицательные координаты работают так же. Строки не содержат артефактов
  вида `0.30000000000000004` для шага 0.1 mm.
- Drag сохраняет исходный grab offset и считает желаемую координату от состояния
  нажатия, затем привязывает только оси, по которым есть смещение. Нажатие без
  движения и ось с нулевым смещением сохраняют исходную строку, даже если она
  не кратна шагу. Возврат указателя точно к исходному нажатию восстанавливает
  исходные строки и остаётся no-op. Остальные вершины не изменяются. Шаг
  фиксируется в момент press; управление Snap недоступно во время активного drag.
- Snap Off сохраняет прежнюю точность пикселей. Поля X/Y всегда принимают точные
  значения пользователя без привязки. Переключение Snap само по себе не двигает
  вершины и не добавляет Undo.

Жесты, история и отмена остаются контрактом [§25C](sketch-vertex-drag.md):
один изменивший контур жест — один Undo; Escape / потеря фокуса / PointerGone
отменяют до исходного State; release за canvas завершает; no-op, несколько
жестов в одном кадре и 128 состояний не менялись. События по-прежнему
обрабатываются по порядку.

Привязка может создать coincidence, crossing или вырождение. Диагностика —
прежняя общая `PolygonExtrusion` / `SketchChoice` policy; недопустимый draft
остаётся видимым для исправления, Save недоступен. Второго алгоритма
допустимости нет; finite/range/winding и сегментные ограничения не ослаблены.

## Сохранение и CLI

Сохранение идёт через существующие jobs. UUID, topology refs, source claims,
SQL cells, snapshot/version/Keep guards не менялись. CLI не имитирует мышь:
конечные координаты уже доступны через
[create-sketch-extrude](sketch-extrude-create.md) и
[edit-sketch-copy](edit-sketch-copy.md). Новых CLI-команд, JSON-полей,
геометрических операций и solver constraints нет.

Рецепт L 60→80 остаётся исполняемым точными числами. В UI тот же итог
получается мышью при Snap 1 mm: слегка неточные пиксели обеих правых вершин
дают ровно 80 mm без правки полей. Cold rebuild и независимый STL — 80×40×10 mm,
20000 mm³.
