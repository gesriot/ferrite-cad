# 6. A generic parametric modelling core replaces bounded feature slices

**Status:** accepted, 2026-10-16. Partially supersedes
[ADR 0004](0004-feature-predecessor.md) (§26C–§26E's bounded catalogue) and
[ADR 0005](0005-document-session.md) (Apply as a reused copy operation and cold
rebuilds on every Apply). Their other rules remain in force.

## The problem

Each new feature costs more as existing features multiply: the editor recognises
combinations of document shapes rather than composing general operations. A user
cannot build an arbitrary part through the supported modelling path.

The code at the time of this decision made that cost visible:

* **Whitelisted geometry.** [The evaluator](../../crates/ferritecad-eval/src/cold.rs)
  calls `evaluable_fillet` in the [document crate's Fillet policy](https://github.com/gesriot/ferrite-cad/blob/40a675e1ae705c425274db1a13e9db6c3a83faba/crates/ferritecad-document/src/fillet.rs).
  It permits only vertical corners of a rectangular plate, up to
  `MAX_PLATE_FILLETS = 4`; [Chamfer](https://github.com/gesriot/ferrite-cad/blob/40a675e1ae705c425274db1a13e9db6c3a83faba/crates/ferritecad-document/src/chamfer.rs)
  permits one such corner with no Cut or Fillet. The
  [Cut editor](../../crates/ferritecad-document/src/cut_edit.rs) admits up to
  `MAX_CIRCULAR_CUTS = 16`, including on supported simple Line polygons, not just
  rectangles. Radius, distance, spacing and dependent-feature fit are checked
  analytically in the document crate. [Conversion](../../crates/ferritecad-eval/src/convert.rs)
  defines ThroughAll through `Reach`: the first forward Blind extrusion's height
  on the same datum. Add/boss is not implemented.
* **An adapter for each edit.** [CopyWrite](../../crates/ferritecad-jobs/src/edit.rs)
  has separate variants for feature and profile edits; the
  [session's StepTicket](../../crates/ferritecad-jobs/src/session.rs) exposes
  separate methods. [CLI commands](../../crates/ferritecad-cli/src/main.rs),
  [AppEvent and forms](../../crates/ferritecad-app/src/main.rs), and slice contracts
  repeat those distinctions for supported combinations.
* **Enumerated topology.** [SemanticRole and SweptEdge](../../crates/ferritecad-document/src/model.rs)
  and the flat [FeatureNames/CarriedName maps](../../crates/ferritecad-topology/src/map.rs)
  catalogue roles by feature. Fillet/Chamfer select only `SweptEdge` (producer plus
  a pair of profile Lines). General references also name Extrude cap edges and
  cap vertices, and selected names survive operation history, but there is no
  general name for an edge generated by a boolean, Fillet or Revolve.
* **All-or-nothing opening.** A feature error aborts the
  [rebuild](../../crates/ferritecad-eval/src/cold.rs), and
  [scene preparation](../../crates/ferritecad-scene/src/prepare.rs) propagates it;
  the window cannot open that model for repair.
* **Repeated rebuilding.** `edit_object_copy` runs a cold baseline and a cold
  candidate rebuild; scene preparation runs a third after a successful Apply.
  `rebuild_cached`, change-based `plan_rebuild` and `dirty_set` exist in the
  [evaluation crate](../../crates/ferritecad-eval/src/lib.rs), but the interactive
  path does not use them. The full-plan helper uses dirty propagation internally;
  there is no edit/rebuild benchmark corpus. The existing
  [solver comparison lab](../../crates/ferritecad-solver-lab/src/lib.rs) measures a
  different problem.
* **Mixed numbers.** [The model](../../crates/ferritecad-document/src/model.rs)
  stores `Expression` in Extrude extents and `Parameter`, but Fillet/Chamfer and
  sketch constraints use `f64`. Revolve angles are stored in degrees; sketch
  directed angles already use radians. The evaluator does not evaluate
  `Parameter` or expression source text; it consumes saved expression values.
* **Verification and format overhead.** At version 0.0.1 the model declares 19
  capabilities and 21 readable payload layouts across nine object kinds (12
  beyond their initial layouts). Tracked Rust test files and test modules total
  roughly 2.5 physical lines per product Rust line. The
  [workflows](../../.github/workflows) total 9,944 lines, including gates keyed
  to individual test names. Those counts describe this decision's baseline,
  not targets for future changes.

## What was decided

### D1. General operations

A feature applies to whatever geometry it receives. The kernel decides whether
it can be built when the operation runs. Remove document-shape whitelists and
analytic fit pre-checks as their generic replacements arrive, including checks
that predict whether dependent features will still fit.

### D2. The model always builds; each feature has a status

A rebuild reports every feature as **built**, **failed** with its error, or
**skipped** because a dependency failed. Accept an edit or transaction only if it
introduces no failed feature that was not failing before. A refusal lists every
feature that would fail and its reason, rather than stopping at the first one.

An edit that would otherwise break dependents is one transaction: for example,
change a sketch and its Fillet together. A document that no longer builds on its
own after a kernel update or tolerance change still opens, with failures marked,
so it can be repaired. Structural errors such as cycles or corrupt payloads, and
cancellation, remain errors of the whole operation.

### D3. Generative topological naming

Derive output names from input names through operation history: generated,
modified and deleted. Name an edge or vertex through adjacent named faces.
An unresolved or ambiguous reference fails the feature that uses it and names
the reference; it never selects a neighbour. ADR 0007 and a prototype in task 07
will define the detailed design; task 08 integrates it and removes the role
catalogues.

### D4. Every model number is an Expression

Store model numbers as `Expression`s in internal units: millimetres and radians.
Display units and conversion belong only at the UI and CLI boundary.

### D5. One transactional edit path for UI and CLI

Validation, changes, rebuild and publication have one library transaction API.
An open document keeps a live evaluated model and a kernel session and rebuilds
incrementally. The cache is trusted and keyed by a hash of its inputs. Cold
rebuild remains the test reference and the explicit `ferritecad rebuild --cold`
route, rather than the path behind every click. That command option and the live
path are targets of this migration, not claims about the current implementation.

### D6. The file format is unstable

Change the format whenever a task needs it, without migrations, compatibility
code, version checks or messages for older documents. Regenerate affected
fixtures. Unknown object types and unreadable payloads are structural errors of
the entire opening operation, reported with the object identity and type.

### D7. Verification is proportionate to the change

Use ordinary `cargo test` tests and run the entire native suite in CI. Every
workflow runs automatically, however long it takes. Add no gates keyed to test
names, execution markers or verification documents. This decision sets the
direction for replacing the existing workflow catalogue; this documentation
change does not change workflow triggers.

### D8. Prioritise the modelling core

New packaging, SBOM and FBX/Unity work requires a separate maintainer decision.

## What stays

* The SQLite container, CBOR object envelopes and separate cache sidecar.
* References by identity rather than index, with refusal instead of retargeting.
* The C ABI to OCCT and `GeometryKernel`.
* `DocumentSession`: Save, conflicts, dirty state, history and recovery.
* The viewport and GPU rendering.
* The PlaneGCS wrapper.
* The licensing policy.

## Migration order

* 03 Per-feature rebuild status; documents that no longer build open for repair; refusals list every failing feature
* 04 Benchmark corpus; one rebuild per Apply instead of three
* 05 Every model number an Expression in mm/rad; drop compatibility machinery
* 06 One transaction API for UI and CLI instead of per-feature copy jobs and their analytic pre-checks
* 07 Topological naming: ADR 0007 and a prototype of generated names
* 08 Naming integration; remove SemanticRole/SweptEdge/CarriedName roles
* 09 Generic Extrude/Revolve: new body, boss, cut, all end conditions, regions, axes
* 10 Generic Fillet/Chamfer on any edge set of any body
* 11 Datum planes and sketches on faces
* 12 Live evaluated model and incremental rebuild in the session
* 13 UI command framework, feature tree (edit, delete, suppress, rollback), 3D selection
* 14 Sketcher in the 3D viewport
* 15 Expressions and a parameter table

## Consequences

Much of the narrow implementation, its tests and its slice documentation will
be deleted as the generic paths replace it. Older documents may stop opening
without a compatibility warning: the program has not been distributed yet.
Task 04 will measure edit response time on larger models before optimisation.
